  📝 파일 분할 동기화 및 정각 정렬 개선 계획서


  1. 개요
  현재 gstApp(영상)과 vcm(자막)은 부팅 직후 또는 특정 상황에서 시스템 부하로 인해 00초 정각 분할 타이밍을 놓치는 경우가 발생합니다. 이를 해결하기 위해
  "정확한 시간 일치(==)" 방식에서 "목표 시간 도달 확인(>=)" 방식으로 로직을 개선하고 두 프로세스 간의 동기화 메커니즘을 강화합니다.

  2. gstApp (영상 녹화 프로그램) 수정 사항


  A. 타이머 정밀도 개선 (main.cpp)
   * 현상: 1초 주기 타이머(g_timeout_add_seconds) 사용 시 시스템 부하에 따라 00초를 건너뛰는 현상 발생.
   * 수정: 타이머 주기를 500ms(g_timeout_add)로 단축하여 정밀도 향상.


  B. 분할 트리거 로직 개선 (splitCheck 함수)
   * 기존: if (target_min != min || startSec != sec) (정확히 일치할 때만 동작)
   * 수정: 목표 시간(00초) 대비 현재 시각의 차이(diff)를 계산하여 0초 이상 경과 시 즉시 트리거.
   * 다양한 녹화 시간(`duration`) 대응: 1, 2, 3, 5분 등 설정값에 상관없이 target_min을 현재 시각 기준 (min + duration) % 60으로 업데이트하여 유연하게 대응.
   * 시간 역전 보정: 59분에서 00분으로 넘어가는 시점의 산술적 오류 보정 로직 추가.


  3. vcm (자막/데이터 프로그램) 수정 사항


  A. 분할 조건 동기화 (tcpServer.cpp)
   * 수정: waitingMakeSRT 루프 내의 파일 전환 조건을 gstApp과 동일한 "시간 경과(diff >= 0)" 방식으로 변경.
   * 효과: 영상 파일이 00.1초에 분할되더라도 자막 파일이 즉시 따라오도록 설계.


  B. 강제 재동기화 로직 강화
   * 현상: gstApp이 강제 split-now를 수행할 때 자막 파일이 따로 노는 현상.
   * 수정: gstApp이 /tmp/start_video_time 파일을 갱신할 때 vcm이 이를 감지하고 즉시 set_start_time 단계로 복귀(Jump)하여 타임스탬프를 다시 맞춤.

  4. 동기화 메커니즘 (Synchronization)

  5. 기대 효과
   1. 정밀한 동기화: 영상과 자막의 파일 분할 시점 차이를 1초 미만(최대 500ms)으로 단축.
   2. 부팅 안정성: 부팅 직후 시스템이 바쁜 상태에서도 정각 정렬 로직이 유실되지 않고 반드시 실행됨.
   3. 유지보수 용이성: 1, 2, 3, 5분 등 다양한 녹화 주기에 대해 별도의 하드코딩 없이 자동으로 대응.
   4. 시스템 신뢰도: 감시 스크립트(chk_cam_operate.sh)에 의한 불필요한 앱 재시작 방지.
