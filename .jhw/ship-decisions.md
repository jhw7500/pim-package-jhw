## PR #39 — 바이너리 검증 CI

### declined

- **Actions 버전을 커밋 SHA 로 고정** (Claude, MEDIUM)
  타당한 공급망 지적이지만 이 저장소의 워크플로우 15개가 모두 태그(`@v4` 등)를 쓴다.
  새로 추가한 2개만 SHA 로 고정하면 일관성이 깨지고, 나머지는 그대로 노출된 채로
  남아 실익이 적다. 저장소 전체 정책으로 한 번에 다루는 게 맞다. 별도 변경 대상.

- **`update-binaries.yml` 의 case 문을 매니페스트에서 읽도록 일반화** (Gemini, LOW)
  대상이 3개뿐이고, 매니페스트에는 상위 저장소 자산 이름(`ASSET`)이 없어 스키마를
  먼저 늘려야 한다. 지금 하면 이 PR 범위를 넘고 이득은 미미하다. 대상이 늘어날 때
  다시 본다.

- **`pointer_size` 가 파일 전체를 읽는다** (OpenCode, LOW)
  LFS 포인터는 130바이트 남짓이다. 청크 읽기로 바꿔도 측정 가능한 이득이 없고
  코드만 길어진다.

- **`sc16is7xx_ext.ko` 의 mode 를 644 로** (Claude·OpenCode, MEDIUM/LOW)
  매니페스트는 현실을 기록해야 한다 — 644 로 적으면 즉시 오경보가 난다. 파일 자체는
  최초 추가(2025-09-18)부터 755 였고 `postinst` 는 `/lib/modules/*/extra/` 로 복사만
  하므로 모듈 로드에 exec 비트는 무관하다. 파일 모드를 바꾸는 별도 변경으로 다룬다.
  추적을 위해 매니페스트 note 에 사유와 계획을 남겨 뒀다.
